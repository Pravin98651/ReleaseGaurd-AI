# ReleaseGuard AI — Known Limitations & Scope Boundaries

1. **Two-Arm Bayesian Scope on Multi-Variant Flags:**
   - `backend/app/analytics/bayesian.py` (`BayesianCountsInput`) models **one Control arm vs. one Treatment arm**. On 3-variant Flagsmith flags such as `#503` (`control` 34%, `one_page_checkout` 33%, `simplified_checkout` 33%), the third variant is excluded into `unattributed_events` unless mapped via `variation_map`.
2. **Flagsmith Native Results Warehouse Lag:**
   - Flagsmith Cloud `GET /experiments/503/results` returns `variants: {}` (`is_final: false`) because conversion/guardrail telemetry for Bayesian decisions is ingested into ReleaseGuard's PostgreSQL `experiment_events` table via `POST /api/v1/events/ingest` (`tracked_event_fallback`).
3. **Synthetic Demo Traffic in NovaShop:**
   - Shopper cohorts generated by `demo-app/backend/app/simulator.py` and `phase1_live_proof.py` are deterministic synthetic cohorts (`synthetic_test_traffic: True`), explicitly labeled `Simulated` in the UI (`EvidenceBadge`). They are never claimed as real production shoppers.
4. **Estimated Manual Benchmark Baselines:**
   - Automated Flagsmith timings (`mean=5.7719s` across 3 live trials) are `VERIFIED_MEASURED`, whereas manual engineering comparison baselines (`1200.0s`) are explicitly labeled `ESTIMATED`.
5. **NovaShop Shopper Authentication Scope:**
   - `POST /api/auth/login` in `demo-app` is a demonstration identity-binding endpoint for testing Flagsmith targeting/segments (`consumer`, `internal`, `qa`, `enterprise`) and is not an OAuth/production identity provider.
6. **Three-Minute Walkthrough Video:**
   - `docs/HACKATHON_VIDEO_SCRIPT.md` and `docs/FLAGSMITH_HACKATHON_REQUIREMENTS_DEMO.md` are complete; final video recording/upload is a non-code submission step.
